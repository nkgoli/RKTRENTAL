### Navigation and save rules

`WIZARD_STEPS` in `types.ts` is the authority. `step` and `furthestStep` are zero-based. Only a non-current step at or before `furthestStep` is available, and it is disabled while pending; unvisited steps remain visible and noninteractive. A visited check marker means the step was passed in navigation, not that every field is permanently valid. Term's footer Back is disabled at index 0.

Next runs local `validateStep`, then a strict server save, and advances only on success. Back/visited-step navigation saves non-strictly when a lease ID exists; without an ID it changes the local step. Save and exit saves non-strictly without requiring the step to be complete. This is explicit saving, not autosave. Saved-step/furthest-step values and entered draft values must survive resume. A failure leaves the step and values in place.
