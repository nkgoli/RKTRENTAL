## Changes and preserved behavior

- Changes are confined to the tenant/auth routes, root entry/boundaries, TenantShell and its scoped stylesheet, tenant/auth tests, the root E2E expectation and this report.
- New small components separate sign-in controls, repair-form feedback and tenant photo fallback. Scoped portal styles handle section links, documents, confirmation and payment status; shared global CSS was not edited.
- The pay action now rejects an unconfirmed submission before calling the payment service. The reviewed amount and authenticated tenant are tested against an isolated mocked service. No provider adapter, ledger arithmetic, fee calculation or access rule was changed.
- Sign-in still authenticates with the existing credential service, cookies, rate limiting and safe role redirect. Passwords are not logged or retained by the new UI.
- Lease downloads, preview URLs, unit-photo access, renewal/move-out notices, saved payment methods, autopay, upload controls, repair priorities and comments remain available.

## Limitations and design allocation

- Designs/rocketrental-app already has 40 screens. Separate sign-in, sign-out and recovery screens were rejected with `DESIGN_SCREEN_LIMIT`. The owned tenant-home screen now includes these as clearly labeled reference views beneath the primary Home design, explicitly separated from the application's actual Home flow. No unrelated screen was removed or changed. Invalid credentials, signed-out feedback, not-found, retry and no-active-lease views are represented there.
- The seeded tenant has a lease, receipts, documents and repair history. No-active-lease and empty variants use isolated rendering/data tests rather than altering that tenant's records. Runtime exception recovery was reviewed through the shared component and source; the running server was not deliberately broken.
- Financial writes, autopay persistence, repair creation/comments, file uploads and destructive flows were not exercised against the existing data. The five database integration tests remain skipped. Payment mutations were verified only with mocked actions/services.
- Existing missing assets are not repaired or deleted. The portal now presents a stable unavailable-photo state while preserving the source URL and access rules.
- This report records a source candidate and observed checks. Git integration, remote push and Preview publication are separate states and are reported only if performed.
