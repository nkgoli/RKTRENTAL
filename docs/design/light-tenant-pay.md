## Bounded production navigation repair

The inherited hydrated server-action payment flow could record a successful mock charge and return `/pay?notice=paid` while leaving the page at Submitting payment. The original base payment files reproduced the same failure on controlled build `j0Tj_M0KyDWoEH3R28VSe`. The final pre-repair exclusive build `tiqF72QfIRRRF5OoOQXfk` had four passing browser tests and that one card regression failure. Earlier failed checks are durable owner observations; the old test-results failure screenshot was not retained, so no before-failure screenshot is claimed.

The manager authorized repair within this Task. The existing tenant Repairs submit/comment native result routes were inspected. The payment form now posts once to `/pay/submit`, which returns a **303 to a GET** of `/pay?notice=...#payment-result`. This is the actual submit-to-receipt flow, not a test reload or a retry workaround. The endpoint requires the current tenant session and retains the browser-origin boundary. It uses a shared `submission.ts` helper extracted from the original payment action; the compatibility `payRentAction` calls that same helper. Authorization inputs, amount/token validation, payment service, provider charge, ledger and idempotency logic are unchanged.

A synchronous submission ref prevents a second submit event before a render; Confirm/Back lock while pending. A conditional hidden confirmation field preserves the explicit-confirm value when the native submit button becomes disabled. Browser Back from a persisted page clears the stale pending/review state. The result route never retries payment. Known validation/service failures retain existing notices. An unexpected service/transport failure instead reports **We could not confirm the payment result. Check your recent receipts before trying again.**, because a charge may already have completed. This new uncertainty message is a justified recovery addition, not a claim that nothing was charged.

Repair paths: `PayForm.tsx`, `actions.ts`, `submission.ts`, `submit/route.ts`, `PaymentNotice.tsx`, `page.tsx`; affected tests under `tests/tenant-pay`. No other application path or backend policy was changed.
