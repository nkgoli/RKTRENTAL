## Original run limitations and delivery boundary

In the original ROI Task, the Rent selector mismatch was outside its assigned paths: `src/app/(manager)/rent-comps/FilterBar.tsx` used `defaultValue={unitId}` without a changing form key, so client-side prop changes could leave the old visible selection. Its typed question requested scope/owner direction, and its navigation evidence was correctly reported as incomplete. The separately scoped follow-up at the top of this handoff now repairs and verifies that limitation, including every visible filter control after Reset/history. The original failure screenshot remains historical evidence.

This run did not apply a market rent, inject native transport/CAS races or contact a live comps provider. Focused automated tests cover the lifecycle failures, while historical benchmark source metadata remains unrefreshed and unverified. Charts and comparisons use modeled assumptions, not live returns.

The isolated app and database were stopped after checks, retaining their dedicated data. This is a committed local candidate and evidence, with no integration, push or Preview publication claimed. The completion report identifies the exact final commit.
