## Production redirect repair and final runtime

The original visual candidate `03e4dbec75d1c694225f905aedb116a80a7eb614` and the exact unchanged foundation both reproduced the production defect: the screening POST returned 303 with the notice destination and complete applicant Flight content, but the client applied it as an empty route body. This baseline evidence is preserved. Removing explicit revalidation did not reliably repair the flow and was abandoned; revalidation remains intact.

The bounded repair adds `/applications/result`. Screening and decision actions redirect through that authenticated endpoint. Its internal RSC request returns a non-Flight, uncached response, causing Next's existing document-navigation fallback; the browser receives a relative, same-origin 303 to the original application URL and query. Relative Location preserves the browser host behind proxies and when localhost differs from 127.0.0.1. Only the four original result parameters are forwarded. No provider operation, validation, authorization, mutation, revalidation, final URL or hidden form field was removed or replaced. No framework upgrade or shared-shell edit was needed.
