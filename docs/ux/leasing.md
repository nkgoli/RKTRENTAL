### Isolated fixtures and runtime

Created only the new database `rr_leasing_ux_06f7dadc` on the existing local PostgreSQL service at `localhost:5433`. Applied the 18 repository migrations with Prisma `migrate deploy`, then ran the existing seed with `node --import ./prisma/os-userinfo.mjs --import tsx prisma/seed.ts`. This produced the demo portfolio (45 units and 41 leases). The tests use this database; the live app database was not used for submissions. The integration test's outdated first-month charge expectation was aligned with the existing canonical `prorated:<lease>:<start-date>` key, retaining its exact amount and duplicate-charge assertions. No ledger source was edited.

The prepared review address was `http://127.0.0.1:3114`, backed by this database and scoped local storage. This is **not an observed existing-Edge URL**: Edge ownership was never acquired, so the actual URL in the human's Edge session could not be inspected or recorded. The foundation report's `localhost:3101` is prior evidence only, not a runtime verified by this Task.

The first temporary Next helper did not propagate its custom dist configuration to development/build workers and collided with shared `.next` output. Its process was stopped. Subsequent helpers use an isolated dist directory and a worker-visible resolved config. Initial missing-manifest, alias-resolution and deprecated-baseUrl failures were confined to this temporary setup; the corrected production build passed. No shared Next configuration or application route was changed to work around the environment. Temporary scripts, dependencies, database-related files and caches remain ignored under `tests/leases/.runtime/` and are not deliverables.
