# People and applications UX review

Polish tenants and application review: compact directory and profile hierarchy, reliable context links, readable phone layouts, and explicit screening/decision states. Reviewed October 18, 2026.

## Basis and scope

- Read the foundation's `docs/ux/full-app-review.md`; verified its declared source commit is present and an ancestor of this checkout before implementation.
- Read `Diagrams/rocketrental-mindmap` revision 4, including tenant management and listings/applications/screening. Tenant contacts, assignment, history, lifecycle, consent, permissions and provider responsibilities remain intact.
- Read the latest `Designs/rocketrental-app` at the start of work (revision 288). Updated only `tenants`, `tenant-detail`, and `screening`, with individual screen writes against current revisions. Shared CSS and other screens were preserved.
- The `properties` design is an already coherent navigation reference owned by the portfolio work. Its shell and Properties-style tabs are reused, not rewritten here.
- All source changes stay within the assigned tenant/application routes, the scoped `ApplicationsPanel`, their local styles, tests, and this report.

## UX decisions and preserved behavior

- Flat, compact controls and section headings use the foundation's theme variables. Borders separate groups; whitespace no longer depends on large isolated cards. Responsive records retain the directory and checklist information.
- Portfolio totals are labeled independently of filtered results. Query state is carried by GET forms and local links. Tenant return destinations whitelist `/tenants` and approved filter keys; external URLs cannot become return links.
- Application decision status is distinct from report completion. No consent still prevents screening; complete reports and current consent are still required for review decisions. Manager/organization guards and server validation remain the authority.
- Existing draft/current/past lease behavior, document preview/download, notes, payment history, lifecycle actions, archive handling and global screening settings remain available. No schema, data, provider or shared-component changes were made.
- The native phone review exposed provider text squeezed by its status badge; the header now places the badge on its own row. Native profile editing exposed the Decimal serialization issue; selecting only contact fields repaired it. Accessibility checks also corrected heading order and underlined contextual profile links.

## Limitations

- No successful tenant creation/update, note, lifecycle, screening order, decision, settings save, financial action or destructive action was submitted to the shared demo database. Browser form submissions were deliberately invalid; valid decision behavior is tested with mocks. Provider delivery, real report contents and lifecycle persistence were not end-to-end tested here.
- Permission/service behavior is covered by existing code and focused tests, not a separate live multi-role browser matrix. Error recovery for unavailable selections and invalid fields was rendered; a database outage was not induced. Less common lease/archived/provider-failure fixture branches received source review as identified above.
- This submission is a committed source candidate with evidence, not a claim of merge, push, production deployment or Managed Preview publication.
